Sweet Thuty Patisserie

Dicionário de Dados — Banco de Dados da Confeitaria

Sobre o projeto

Este dicionário de dados apresenta as entidades e os atributos do banco de dados da Sweet Thuty Patisserie. O objetivo é organizar as informações de clientes, pedidos, produtos, pagamentos, receitas, fornecedores e estoque.

Os tipos de dados apresentados são sugestões para implementação em um banco de dados relacional.

Entidades

Usuário Cliente Pedido Item do Pedido Categoria Produto Receita Item da Receita Insumo Estoque Movimentação de Estoque Fornecedor Compra Item da Compra Pagamento Financeiro

USUÁRIO

Armazena os dados dos usuários que acessam o sistema.

Atributo Tipo Obrigatório Descrição
id_usuario PK INT Sim Identificador único do usuário.
nome VARCHAR(100) Sim Nome completo do usuário.
login VARCHAR(50) Sim Nome utilizado para acessar o sistema.
senha_hash VARCHAR(255) Sim Hash da senha do usuário.
nivel_acesso VARCHAR(20) Sim Perfil de acesso ao sistema.
ativo BOOLEAN Sim Indica se o usuário está ativo.

CLIENTE

Armazena os dados dos clientes cadastrados.

Atributo Tipo Obrigatório Descrição
id_cliente PK INT Sim Identificador único do cliente.
nome VARCHAR(60) Sim Nome do cliente.
sobrenome VARCHAR(80) Sim Sobrenome do cliente.
telefone VARCHAR(20) Sim Telefone para contato.
endereco VARCHAR(200) Sim Endereço do cliente.

PEDIDO

Registra as vendas, encomendas e pedidos de delivery.

Atributo Tipo Obrigatório Descrição
id_pedido PK INT Sim Identificador único do pedido.
id_usuario FK INT Sim Usuário responsável pelo registro.
id_cliente FK INT Condicional Cliente associado ao pedido. Pode ficar vazio em vendas presenciais.
tipo_pedido VARCHAR(20) Sim Pronta-entrega, encomenda ou delivery.
status VARCHAR(20) Sim Situação atual do pedido.
data_pedido DATE Sim Data de registro do pedido.
data_entrega DATE Condicional Data prevista para entrega ou retirada.
hora_entrega TIME Não Horário combinado para entrega ou retirada.
valor_total DECIMAL(10,2) Sim Valor total do pedido.
observacoes TEXT Não Observações gerais sobre o pedido.
foto_referencia VARCHAR(255) Não Caminho ou link da imagem de referência.

ITEM_PEDIDO

Registra os produtos e as quantidades de cada pedido.

Atributo Tipo Obrigatório Descrição
id_item PK INT Sim Identificador único do item.
id_pedido FK INT Sim Pedido ao qual o item pertence.
id_produto FK INT Sim Produto incluído no pedido.
quantidade INT Sim Quantidade solicitada.
preco_unitario DECIMAL(10,2) Sim Preço unitário acordado com o cliente.
personalizacao TEXT Não Detalhes da personalização do produto.
subtotal DECIMAL(10,2) Calculado Quantidade multiplicada pelo preço unitário.

Atributo Tipo Obrigatório Descrição

nome VARCHAR(60) Sim Nome da categoria.
descricao VARCHAR(200) Não Descrição da categoria.
ativo BOOLEAN Sim Indica se a categoria está ativa.

PRODUTO

Armazena os produtos comercializados pela confeitaria.

Atributo Tipo Obrigatório Descrição

descricao TEXT Não Descrição do produto.

RECEITA

Atributo Tipo Obrigatório Descrição
id_receita PK INT Sim Identificador único da receita.
id_produto FK INT Sim Produto associado à receita.

Atributo Tipo Obrigatório Descrição

Registra as compras de ingredientes e materiais.

id_item_compra PK INT Sim Identificador único do item comprado.
id_compra FK INT Sim Compra correspondente.

PAGAMENTO

Registra os pagamentos dos pedidos, incluindo sinal, pagamentos parciais e quitação.

Atributo Tipo Obrigatório Descrição
id_pagamento PK INT Sim Identificador único do pagamento.
id_pedido FK INT Sim Pedido associado ao pagamento.
valor DECIMAL(10,2) Sim Valor pago nesta transação.
forma_pagamento VARCHAR(20) Sim Débito, crédito, Pix, dinheiro ou VR.
tipo_pagamento VARCHAR(20) Sim Sinal, pagamento parcial ou quitação.
status_pagamento VARCHAR(20) Sim Pendente, confirmado ou estornado.
data_pagamento DATE Sim Data do pagamento ou registro.

FINANCEIRO

Registra entradas e saídas financeiras da confeitaria.

Atributo Tipo Obrigatório Descrição
id_lancamento PK INT Sim Identificador único do lançamento.
id_usuario FK INT Sim Usuário responsável pelo lançamento.
id_pagamento FK INT Não Pagamento relacionado à entrada financeira.
id_compra FK INT Não Compra relacionada à saída financeira.
tipo VARCHAR(10) Sim Entrada ou saída.
descricao VARCHAR(200) Não Descrição do lançamento.
valor DECIMAL(10,2) Sim Valor do lançamento financeiro.
data_lancamento DATE Sim Data do lançamento.

Regras de negócio

  • Um cliente pode ter vários pedidos em andamento.
  • Um pedido pode ter mais de um pagamento, incluindo sinal e quitação posterior.
  • As formas de pagamento aceitas são cartão de débito, cartão de crédito, Pix, dinheiro e VR.
  • Os pagamentos podem estar pendentes, confirmados ou estornados.
  • O preço de encomendas personalizadas pode variar conforme a solicitação.
  • O preço efetivamente combinado deve ser registrado no item do pedido.
  • Encomendas e delivery exigem cadastro do cliente.
  • Vendas presenciais de balcão podem ser registradas sem cadastro do cliente.
  • O estoque deve registrar separadamente as quantidades de cada insumo na cozinha e no depósito.
